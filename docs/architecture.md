# Architecture

The Vite/TypeScript frontend renders a single transfer screen, plus static educational pages. The Node/TypeScript server keeps a volatile map of WebSocket connections, device information and discovery scopes. It forwards SDP/ICE signaling only between members of a shared scope. It holds no transfer file bytes. Presence changes are broadcast on connect/disconnect; a 30-second ping/pong removes dead connections. A reconnection creates a new identity. Connections expire after 12 hours and reconnect with a fresh identity.

## Discovery

The production server groups by an HMAC of the exact client IP using an ephemeral server secret. The local development server (`--lan`) additionally discovers private IPv4 subnets from the host's directly attached interfaces and netmasks. A loopback connection is included in all such local subnets. IPv4-mapped IPv6 addresses are normalized. Unrelated subnets remain isolated; IPv6-only peers do not gain subnet matching. This is a best-effort subnet grouping, not a verified Wi-Fi boundary: a multihomed host, VPN or a large subnet may include unintended people. It is designed for trusted LAN development only, and must not be exposed to the public internet. The server and host still see IP addresses. There is no QR or code fallback. SDP and ICE exchange are not end-to-end authenticated.

## Transfer protocol

A reliable ordered WebRTC DataChannel sends a metadata offer; the receiver validates it and approves or declines. Once accepted, the sender reads and hashes bounded 1 MiB batches, sending sequence-numbered chunks sized to the negotiated SCTP message limit (up to 256 KiB including the frame header). The receiver verifies monotonic sequence, batches writes and hashing, and cumulatively acknowledges each batch after hashing and the storage write complete. Hashing can overlap with network or storage work. A 4 MiB in-flight window and bufferedAmount limits provide event-driven cooperative backpressure. End-of-file contains the sender's digest; the receiver compares its own digest and acknowledges before the next file. The verified file is written to a user-selected directory when supported; otherwise a browser download is requested and a copy is retained for re-download. One chunk is copied into a framed buffer on send and another on receive; memory is bounded for well-behaved peers, but adversarial flood testing remains necessary.

OPFS writes use asynchronous writable streams and quota checks where available. In browsers without OPFS, bounded Blob segments are written to IndexedDB. Verified segments and history metadata are retained for re-download. The old 128 MiB application cap is removed, but storage quotas and browser implementation limits apply. Retrieving segments and assembling/downloading a Blob may consume significant browser or OS memory; this is not a guaranteed constant-memory download path. Completed files persist in browser storage subject to eviction and site-data clearing. A selected folder stores a real copy outside browser storage, but browser support and permission persistence vary. Directory names receive random suffixes to avoid overwrite. Downloads can be blocked or require approval. Interrupted transfers can leave orphaned OPFS files. Hashing does not require buffering a whole file, but storage/browser implementations have their own memory use. Chunk size is negotiated, not benchmark-adaptive. This version has no restart or resume. Missing/out-of-order chunks and digest mismatches fail instead of being recovered. Disconnection requires starting over. The only ICE default is a public STUN service; optional TURN is operator-configured. The application has not been validated for every browser or multi-gigabyte files.

## Security controls and gaps

The WebSocket server validates the configured Origin, limits message size, has a per-connection message rate and an IP-based connection-attempt rate, caps global connections, and uses heartbeat expiry. These are baseline controls, not a complete abuse-prevention solution. Origin is a browser control, not authentication: non-browser clients can forge it. Same-IP discovery can expose temporary names and categories to strangers behind a shared NAT. Add network-level throttling, infrastructure protections, monitoring, an independent security review, and a trusted TLS proxy before production. A single in-memory server does not support horizontally scaled presence without shared coordination. No database, analytics, advertising, or user accounts are included.
